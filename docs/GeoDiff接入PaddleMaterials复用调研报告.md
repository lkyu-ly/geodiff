# GeoDiff 接入 PaddleMaterials：复用调研报告

**建议：按套件的模型构建、数据加载、训练、采样和发布接口接入 GeoDiff；保留决定构象数值的分子图、去噪器和扩散公式。** 首版范围是已验收的 QM9 配置和动态图（eager）训推。CINN、测速、Drugs 和测试集生成质量不在本轮。

静态调查基于 GeoDiff 本地 `main` 的 `geodiff_paddle/`，以及 PaddleMaterials `upstream/develop`。通过远端查询确认该引用与官方 `develop` 一致，基线是 11 月 20 日合入的 [PR #332](https://github.com/PaddlePaddle/PaddleMaterials/pull/332)；没有使用当前 `feat/chemeleon` 工作树中的专属实现。架构、[Trainer 接入契约](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/trainer_docs.html#d-overview)和[模型包契约](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/model_package.md)有出入时，以目标分支的具体契约和源码为准。

## 从维护者反馈提取的复用规则

- **框架已经负责的工作交回框架。** HIENet 被要求复用[数据类型、dataloader、dataset 和公共激活](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#issuecomment-5677634994)，并核对[已有网络层](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4013936630)和[构图器](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4013940575)；第二轮继续追问[实际字段](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4388869379)和[能否直接用已有数据格式](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4398325784)。GeoDiff 要先证明已有实现是否能按原样读数、拼批和计算，不能只说明文件名不一样。
- **类似功能优先共用装配方式，不用不同算法冒充等价实现。** Chemeleon 收到[参考 scheduler](https://github.com/PaddlePaddle/PaddleMaterials/pull/322#discussion_r4389004553)、[参考或继承现有 dataset](https://github.com/PaddlePaddle/PaddleMaterials/pull/322#discussion_r4608495443)的反馈；HIENet 也被问能否在[公共模块上增强](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4608694201)。对应到 GeoDiff，先比输入、输出、排序、索引及权重语义；仅缺接口时扩展公共接口，任务特有的数值实现只保留实际用到的部分。
- **资源走真实发布路径，代码只留运行可达内容。** 两个 PR 的[词表](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4608656438)、[公共工具](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4608733156)、[未见调用的函数](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4608844465)、[缺失数据](https://github.com/PaddlePaddle/PaddleMaterials/pull/322#discussion_r4389010487)和[注册权重](https://github.com/PaddlePaddle/PaddleMaterials/pull/322#discussion_r4608536001)反馈，要求有实际调用方和可用资产。词表、数据格式、交付渠道是否适用须逐项核对；Chemeleon 的[网盘或微信安排](https://github.com/PaddlePaddle/PaddleMaterials/pull/322#discussion_r4608609335)不是 GeoDiff 已获批准的上传位。

## QM9 数据与拼批

- **读 GeoDiff 作者发布的 GEOM-QM9 split，不换成套件的 QM9。** [作者说明](../geodiff/README.md#L24-L34)区分原始 GEOM 数据库与 [GeoDiff 预处理发布包](https://drive.google.com/drive/folders/1b0kNBtck9VNrLRZxg6mckyVUpJA5rBHh?usp=sharing)。现有 Paddle [配置](../geodiff_paddle/configs/qm9_default.yml#L35-L38)指向 `train_data_40k.npz`、`val_data_5k.npz`、`test_data_1k.npz`，它们来自发布分包的离线导出，不是公开源文件本身；[README](../geodiff_paddle/README.md#L22-L52)里的 `--limit 2` 只是对齐样本，不是完整 split。套件 [`QM9Dataset`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/qm9_dataset.py#L37-L82) 是 GDB9 性质预测 CSV，逐行读 `standard_xyz` 后构图并缓存（[构图](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/qm9_dataset.py#L242-L275)、[返回值](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/qm9_dataset.py#L302-L313)、[样本](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/qm9_dataset.py#L357-L383)）。[`MD17Dataset`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/md17_dataset.py#L66-L83) 虽也读 NPZ，但一个文件是一种固定原子数分子的 `z/R/E/F` 轨迹（[读取](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/md17_dataset.py#L262-L279)）；[`MP20Dataset`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/mp20_dataset.py#L373-L390) 的晶胞、分数坐标及 `ConcatData` 不表达共价键索引。三者可参考装配或下载方式，不能替代数据和 split。
- **新增薄的 `GeomQM9Dataset`（建议名），只接现有 NPZ。** [导出器](../tools/export_paddle_assets.py#L73-L114)沿原文件顺序拼 `atom_type[N]`、`pos[N,3]`、`edge_index[2,E]`、`edge_type[E]`；`node_ptr/edge_ptr` 切回单构象，COO 索引在分子内从零起算。原子是原子序数，边是双向共价键及 GeoDiff 的 RDKit 键类型编号，不是 one-hot 或 ppmat 词表索引（[构造](../geodiff_paddle/utils/datasets.py#L248-L284)、[键类型](../geodiff_paddle/utils/chem.py#L9-L15)）。[读取器](../geodiff_paddle/graph_data/assets.py#L9-L54)用 `allow_pickle=False`，保留原 dtype；训练只需四个核心字段，`idx/totalenergy/boltzmannweight/smiles` 与可选的 `rdmol_ptr/rdmol_data` 按用途读，别在训练热路径反序列化 RDKit 分子。可以用 `paddle.io.Dataset`（[Trainer §2.4](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/trainer_docs.html#L256-L267)）；套件的 [geometric `Dataset`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/geometric_data_type/dataset.py#L60-L105) 是可选 `raw/processed` 生命周期，不是工厂强制的 `BaseDataset`。把类放 `ppmat/datasets/`、导入工厂命名空间，沿用 `dataset.__class_name__/__init_params__`、`loader`、显式 `sampler` 和预分好的文件；不另写 DataLoader 或随机再切 split（[工厂](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/__init__.py#L151-L199)、[采样器装配](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/__init__.py#L254-L304)）。采样需要按分子而非按构象抽样时，再沿用首现顺序按 SMILES 聚合的逻辑（[现有实现](../geodiff_paddle/utils/datasets.py#L780-L809)）。
- **优先复用 `Data → DefaultCollator → Batch`。** 数据集把磁盘的 `atom_type`、`pos` 映射到套件约定的 `atom_types`、`cart_coords`（[Trainer §2.4](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/trainer_docs.html#L256-L267)）；不用重排或缩放数组。给 `Data` 显式传 `num_nodes`，采样图可不带参考坐标。`edge_index` 沿末轴拼接，加前图的原子数；节点和边属性沿首轴拼接，`batch` 标出每个原子的归属，`ptr` 划分图边界，`num_graphs` 给出图数（[`Data`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/geometric_data_type/data.py#L183-L238)、[`Batch`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/geometric_data_type/batch.py#L54-L167)、[图数](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/geometric_data_type/batch.py#L255-L265)）。字段集合保持一致；在模型入口映射 `edge_index/edge_type` 到共价键参数，用 `diff(ptr)` 得到每图原子数（[GeoDiff 调用](../geodiff_paddle/train.py#L109-L135)）。裸变长字典会被递归 `stack`，[两种公共 collator](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/collate_fn.py#L53-L125)中不要选为 PGL triplet 设计的半径 collator。**先验证** `Batch` 经标准 reader 到 worker/设备时字段是否保留；如失败，薄 collator 仍调用 `Batch.from_data_list`，在输出处转成标准 mapping，不重写拼批（[独立版本的传输限制](../geodiff_paddle/graph_data/assets.py#L58-L77)、[套件 `Data.to`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/geometric_data_type/data.py#L279-L309)）。
- **下载复用，分发另定。** 先支持配置直接传本地 NPZ，并写清官方原始入口、完整 split 离线导出方式和对应文件名；运行时不装 Torch/PyG、不读取发布 pickle，也不引入原 CSV 类的逐图 pickle 缓存。若确认可转分发并有正式托管，单独打三个 NPZ 的数据包，记录来源、目录和实际校验值，缺文件时沿用 [`download.get_datasets_path_from_url(url, md5)`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/utils/download.py#L64-L124)，按解压结果定位 split（[MP20 示例](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/mp20_dataset.py#L105-L126)）。不要把数据混进[权重包](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/model_package.md#L1-L15)，也不填未确认的 URL；[Chemeleon 的缺文件反馈](../../Chemeleon/docs/PR322-review意见与调查.md#L54-L73)只说明获取路径要可用，不构成 GeoDiff 的托管授权。

## 图与网络公共件

- **保留 GeoDiff 半径选边规则。** 去噪器用扰动后或当步坐标、同分子且 `d² < r²`，先按索引去自环，再对每个目标取源顺序前 32 个；不同原子即使重合也不排除（[半径算子](../geodiff_paddle/graph_ops/radius.py#L4-L53)、[评估过的 CUDA wheel 行为](../geodiff_paddle/graph_ops/UPSTREAM.md#L32-L38)、[去噪调用](../geodiff_paddle/models/epsnet/dualenc.py#L68-L87)）。公共 [`RadiusGraphConverter`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/common/graph_converter.py#L695-L754) 按距离截最近邻；[`infgcn.radius`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/graph_utils/infgcn_graph_utils.py#L18-L69) 含等号且按距离筛选、返回方向不同；[`spherenet.radius_graph`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/graph_utils/spherenet_graph_utils.py#L19-L63) 隔图但不截邻居。三者都不能直接替换。保留一个按原规则的实现，不改变既有构图器调用方。
- **保留整数高阶边、零类型半径边和坐标投影。** [高阶扩图与合并](../geodiff_paddle/models/common.py#L107-L171)以最短键距补 2/3 跳，编号为 `len(BOND_TYPES)+hop-1`；半径边类型为 `0`，与键边重合不覆盖键类型，按 COO（坐标列表）行主序合并。DiffNMR 的 [`to_dense_adj`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/diffnmr/utils/diffgraphformer_utils.py#L193-L262)为带特征维的图分配浮点缓冲区，不直接替换整型邻接。GeoDiff 的 [等变投影](../geodiff_paddle/models/geometry.py#L5-L14)按 `(源坐标−目标坐标)/边长` 分别给两端加减；不用 converter 的方向、epsilon 或归一化。半径图的 `<` 也与 [SchNet 滤波的 `<=`](../geodiff_paddle/models/encoder/schnet.py#L83-L106) 分开。
- **公共 scatter 可复用，先对拍。** QM9 消息是二维张量按首轴加和，采样居中按图求均值；两边常用数据类型的相应路径均走 `index_add`，均值分母至少为 1（[GeoDiff](../geodiff_paddle/graph_ops/reduction.py#L12-L41)、[套件](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/utils/scatter.py#L152-L220)、[居中调用](../geodiff_paddle/models/epsnet/dualenc.py#L478-L480)）。提交方案中保住空输入、显式 `dim_size`、设备和梯度行为；不用不同实现的 [`scatter_sum_first_order`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/utils/scatter.py#L114-L138)，不带未使用的 `scatter_max`。
- **复用等价原件，保留双编码器。** `ShiftedSoftplus` 可按公共[激活模块](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/common/activation.py#L18-L40)组织，公式仍为 [`softplus(x)-log(2)`](../geodiff_paddle/models/encoder/schnet.py#L55-L62)。公共 [`GaussianSmearing`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/common/radial_basis.py#L31-L45)与镜像公式相同，但首版默认 QM9 [配置](../geodiff_paddle/configs/qm9_default.yml#L1-L15)走 MLP，Gaussian 路径无需随默认配置提交。GeoDiff 的 [MLP](../geodiff_paddle/models/common.py#L43-L77)保留 `layers.*` 与末层语义；[CHGNet](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/chgnet/chgnet.py#L65-L110)用 SiLU，[MEGNet](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/megnet/megnet.py#L160-L192)初始化和层编号不同。公共 [`MessagePassing`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/common/message_passing/message_passing.py#L157-L216)的稠密 COO 流向相符，但用 `index_select` 而非 `gather`；先复用归约，不为套公共类改动整条消息路径。保留 [SchNet](../geodiff_paddle/models/encoder/schnet.py#L65-L153)、[GINE](../geodiff_paddle/models/encoder/gin.py#L9-L63)和[局部分支使用全局边编码器的行为](../geodiff_paddle/models/epsnet/dualenc.py#L101-L107)，包括闲置但仍属发布权重的局部边编码器键。

不复制独立镜像的 `graph_data`、`graph_ops` 通用包、离线转换、回放、独立日志或属性评估脚本。按 YAML、工厂和运行时调用链判定可达性，不只看 import：维护者问过[未找到调用点的指标](https://github.com/PaddlePaddle/PaddleMaterials/pull/318#discussion_r4608844465)，但 [HIENet 调查](../../HIENet/docs/pr318/PR318-review-r3.md#L56-L61)显示配置反射是实际调用。改变前向、损失、反传或参数更新实现的替换，即使数学等价，也先征得同意，接入后单独回归。

## 模型装配和扩散调度

- **复用模型工厂，保持一个参数所有者。** 在 `ppmat/models/geodiff/` 暴露 `GeoDiff`，在 `ppmat/models/__init__.py` 导入，按 `Model.__class_name__` / `__init_params__` 构建（[工厂](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/__init__.py#L202-L268)）。现有 [`DualEncoderEpsNetwork.forward`](../geodiff_paddle/models/epsnet/dualenc.py#L68-L119) 是去噪入口，将它置于模型内部的 `denoise_step`；生成模型公开的 `forward(batch)` 计算按原子取均值的总损失与两路损失，返回 `loss_dict`，`sample()` 单列（[Trainer §2.3](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/trainer_docs.html#L227-L254)）。不套一层改变原权重键，不引入新的运行时或编译开关。
- **扩散时间表与学习率调度分开。** 参考 [DiffCSP 的调度器装配](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/structure_generation/configs/diffcsp/diffcsp_mp20.yaml#L77-L89)，走 [`ppmat.schedulers.build_scheduler`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/schedulers/__init__.py#L41-L65)。公共 [`DDPMScheduler`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/schedulers/scheduling_ddpm.py#L222-L259) 已有 GeoDiff 式 `sigmoid`，也接受 `trained_betas`；优先核对能否复用它构建 `betas`/`alphas_cumprod`。镜像先以 NumPy 计算再转 FP32（[原公式](../geodiff_paddle/models/epsnet/diffusion.py#L30-L52)、[buffer 注册](../geodiff_paddle/models/epsnet/dualenc.py#L53-L60)），不能假设公共 Paddle 建表逐项相同。若直接构建有差别，优先用现有 `trained_betas` 接原表，不再养一份完整 DDPM 实现。模型继续持有根级 `betas` 和 `alphas`（后者是累计乘积），避免重新加载或迁移设备后模型和调度器各持一份不同的状态。
- **不替换正向加噪和反向更新。** GeoDiff 用 `pos + noise × sqrt(1−a)/sqrt(a)` 扰动按图取样的坐标，从距离差得到目标，Global/Local 各自投影回节点后乘 2 和 5（[损失](../geodiff_paddle/models/epsnet/dualenc.py#L149-L205)）；公共 [DDPM `add_noise`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/schedulers/scheduling_ddpm.py#L588-L613) 用 `sqrt(a) × pos + sqrt(1−a) × noise`，会改变带噪半径图。GeoDiff [反向采样](../geodiff_paddle/models/epsnet/dualenc.py#L226-L326)用末段连续时间步、按噪声门限加入 Global 分数、有三种更新公式且每步按分子去中心；公共 [`set_timesteps`/`step`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/schedulers/scheduling_ddpm.py#L293-L374)选择时间步的方式及[反向系数](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/schedulers/scheduling_ddpm.py#L515-L575)不同。复用构建接口和同义的表，不拿通用 `step()` 替代整段算法。

## 训练：复用 BaseTrainer，补齐双路装配

[作者训练代码](../geodiff/train.py#L100-L193)和[对齐后的 Paddle 循环](../geodiff_paddle/train.py#L92-L174)规定的是：总损失反传一次；全模型按去重后的参数做一次全局梯度范数裁剪；两套 Adam 更新各自的参数；验证按原子总数加权，两个 Plateau 各看自己一路的验证损失。现有 `structure_generation/train.py` 负责 [OmegaConf、日志、seed、模型和数据加载](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/structure_generation/train.py#L48-L105)，调用 [优化器和 BaseTrainer](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/structure_generation/train.py#L107-L149)，两段都应保留。

- **复用双 Adam 已有原件，而非另起 Trainer。** [`build_optimizer`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/optimizer/__init__.py#L64-L107) 目前只构建一对；[`Adam`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/optimizer/optimizer.py#L218-L236) 可以接指定的 Layer，已有 [`OptimizerList`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/optimizer/optimizer.py#L478-L522) 可遍历 `step`/`clear_grad`、分别保存状态，但 `get_lr()` 只返回第一路。建议给公共构建器增加显式的多组装配方式，按 `model_global`/`model_local` 选参数，保持原单项配置不变。联合裁剪要发生在第一个 Adam `step()` 之前，不能在两份优化器配置各写一次 `clip_norm_global: 10000`（后者只看到各自的参数）。保留两路学习率、总/分项损失与裁剪前范数的可调频率日志；对齐时 `log_freq=1`、`use_tensorboard: false`，沿用 [BaseTrainer 的日志配置](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/trainer/base_trainer.py#L99-L129)。
- **每个 Plateau 要收到自己的原子均值。** 套件 [Plateau 构建器](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/optimizer/lr_scheduler.py#L782-L847) 已支持 `indicator/indicator_name`；现有 [`SchedulerList`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/optimizer/lr_scheduler.py#L850-L879) 固定 `by_epoch=False` 且无参 `step()`，而 [Trainer 的步级验证](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/trainer/base_trainer.py#L679-L743)只为一套 Plateau 取指标。沿用这两层，建议统一调度时分别派发到子调度器，不写 `if model == GeoDiff`。默认 [eval loss](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/trainer/base_trainer.py#L377-L406)以通用 batch size 更新 meter，不保证是原子数。优先走 [`StreamingMetricBase`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/metrics/streaming_base.py#L32-L62) 和 [`attach_metrics`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/spectrum_elucidation/train.py#L175-L194) 的验证汇总：每次分别累计各路逐原子损失和及原子数，两个 Plateau 从 `eval_metric` 各取一项，不能改成取总 loss。公开采样不加载训练侧指标；若复用同一 YAML 的顶层 `Metric`，采样覆盖 `Metric=null`，否则 [MolecularSampler](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L504-L517) 会返回指标而不是样本。
- **复用原生断点和步级配置。** [`save_checkpoint`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/utils/save_load.py#L243-L259)保存模型、optimizer state 和进度。验证恢复时用步级 `latest` 或 `step_N`：Trainer 在调度前保存 `best`，调度后才保存这两类断点（[顺序](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/trainer/base_trainer.py#L714-L767)）。原生恢复须验证两套 Adam 的矩、两套 Plateau 状态和下一步 LR。作者 [`pretrain` 的 QM9 配置](https://github.com/MinkaiXu/GeoDiff/blob/pretrain/configs/qm9_default.yml)是 5,000 个扩散时间步、训练 batch 64、每 5,000 个更新验证、Adam `lr=1e-3`/`betas=(0.95,0.999)`/无权重衰减，Plateau `factor=0.6`、`patience=10`。将训练节奏映射到 `Trainer.eval_freq_steps`、`max_iter`、`max_epochs`，对照发布配方：作者 `pretrain` 的训练上限是 10,000,000，本地镜像 [QM9 YAML](../geodiff_paddle/configs/qm9_default.yml#L17-L33)是 3,000,000；不可把两者都当发布配方，也不能用小跑的覆盖值改默认。先沿现有单卡 FP32 路径验证，不宣称多卡或混合精度。

备选是做模型专属的训练适配。它可以减少其他模型受影响的范围，但当前 [`before_train`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/trainer/base_trainer.py#L798-L819) 只在训练起点运行，并非验证调度接口；强行从这里接管验证节奏和断点会分散行为。建议只补通用装配和派发的缺口；若必须大改公共训练循环，再单独确认范围和是否拆成前置 PR。

## 公开采样

- **输入是有键分子图，输出沿用原子顺序。** `model.sample(data, **kwargs)` 接 `atom_types[N]`、双向共价键 COO `edge_index[2,E]`、`edge_type[E]` 及显式节点数，多图用 `batch/ptr/num_graphs`；不要求参考坐标。可选 SMILES/MOL/SDF 入口若列入范围，可复用 [`BuildMolecule`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/build_molecule.py#L76-L147)和 [`MolecularGraphConverter`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/common/graph_converter.py#L353-L464)解析原子和双向键；仍须核对显式氢、不加自环，把 PGL 的 `[E,2]` 和 one-hot 映射回原子序数和 GeoDiff 键编号，并拒绝不能映射的键。不要用 XYZ 或化学式猜键，也不直接套用要求恰有一个参考构象的 [`rdmol_to_data`](../geodiff_paddle/utils/datasets.py#L248-L284)。
- **复用 `MolecularSampler` 编排，采样留给模型。** [独立脚本](../geodiff_paddle/test.py#L90-L143) 逐分子聚合参考构象、算 `num_confs`（默认参考数 ×2）、做一次高阶扩图、复制图，随机初始化 `pos_init`，再以 `extend_order=False` 调扩散，每步继续重建半径边（[采样循环](../geodiff_paddle/models/epsnet/dualenc.py#L208-L267)）。公开接口在模型侧做一次高阶扩图，按请求的构象数复用 `Batch.from_data_list` 拼重复图，沿用扩散公式，再按节点边界和构象数拆回每个分子 `[K_i,N_i,3]`。`2x` 只适用于确有参考数的测试模式。不照搬本地 pickle resume、逐样本转储及日志；现有核心即使 CLI 不保存轨迹也每步留 CPU 副本（[源码](../geodiff_paddle/models/epsnet/dualenc.py#L312-L326)），若改成按需留轨迹，应单独确认并验证不改随机数消耗或坐标更新。
- [单批 `MolecularSampler.sample`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L416-L448) 在 `no_grad` 下把有键图交给模型，缺省用 `Sampler.model_sample_params`，显式参数是替换而不是合并，返回模型原值。最小流程是 `sampler.sample(graph, {"num_confs": K})`（`num_confs` 为建议的模型参数），不经数据集、训练统计或 CLI。[dataloader 路径](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L469-L517) 接已有 loader 或 `Sampler.data`，要求 mapping 含 `pred` 序列（[迭代和聚合](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L534-L619)）。建议 `pred` 每项放一个分子的全部构象、原子与键；不要用 `num_candidates` 当构象数，非 retrieval 只保留第一个 candidate 的主结果。关闭 DiffNMR 式绘图、链、retrieval 与指标：可视化把 `pred[i][0:2]` 当离散节点/邻接且依赖 `dataset_infos`（[实现](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L362-L399)）；不配指标时返回汇总结果（[返回逻辑](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L504-L517)）。
- **配置取舍。** `MolecularSampler` 在构造时就读取 `Sampler.data` 和非空的 `Dataset.train`；后者会尝试生成统计，但 infos 工厂只认识 `MSDnmrDataset`（[构造](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L142-L167)、[注册](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/__init__.py#L84-L86)、[拒绝未知类](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/datasets/__init__.py#L338-L352)）。两种做法：
  - **不改套件，建议先用：** 推理 YAML 只放 `Model` 和 `Sampler`，不设 `Dataset.train`，仅批量时配置 `Sampler.data`。也可继续用一份标准训练/发布 YAML，在调用时传 `config_overrides=["Dataset.train=null", "Sampler.data=null"]` 做单图；批量只清 `Dataset.train`，并配 `Sampler.data` 或传入 loader。`Dataset.train=null` 不能写成 `Dataset=null`。本地 `config_path/checkpoint_path` 与注册 `model_name/weights_name` 都在创建 loader 前合并 dotlist，因此两边都有不改 sampler 的路径（[两条载入分支](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L90-L140)、[权重加载](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/molecular_sampler.py#L184-L223)）；按名称仍须有真实注册包。若只要直接模型调用、不要 sampler 的批处理，已有 [`build_model_from_name`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/__init__.py#L271-L294) 只构建模型并加载权重，调用者自行 `eval()` 后传入有键图。
  - **一份标准 YAML，无调用端覆盖：** 若明确要求同一个训练/发布 YAML 保留 `Dataset.train` 且默认按名称即可采样，最小通用扩展是支持 `Sampler.use_dataset_infos: false` 这种显式跳过项（建议名，现无此项），只守住创建训练 loader 和 infos 的分支，不改 `Sampler.data` 或模型查找；缺省保留旧行为。不要为 GeoDiff 假注册 infos 或按类名特判。现有 [DiffNMR 配置](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/spectrum_elucidation/configs/diffnmr/DiffNMR.yaml#L220-L227) 用 `Dataset.train`，模型还从 [`dataset_infos` 读取输出维度](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/diffnmr/diffnmr.py#L54-L75)，因此不能全局取消统计，旧配置和调用方不用迁移。
  - 两种做法下，[现有 CLI 的 `--input_path`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/spectrum_elucidation/sample.py#L29-L51) 都只覆盖 `Sampler.data.dataset.__init_params__.path`，不是单图入口，也不关闭统计；传给 `sample_by_dataloader` 的 `data_loader` 同样不能跳过构造时已有的配置。
- **CLI 与落盘各只补缺的部分。** [`structure_generation/sample.py`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/structure_generation/sample.py#L25-L120)目前只装配 `StructureSampler`，它的化学式/原子数入口不表达化学键，批处理输出是 CIF（[源码](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/sampler/structure_sampler.py#L158-L229)）。[`spectrum_elucidation/sample.py`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/spectrum_elucidation/sample.py#L21-L70)示范了用 `MolecularSampler` 接本地或注册权重、传入 `Sampler.data`，但不落盘普通采样的返回值。**建议沿用 `structure_generation` 的任务域和训练入口，只给公开采样增加一条显式分子图路径**，把批处理和加载交给 `MolecularSampler`，不改已有晶体模式、不新建一套任务框架。第一版用 QM9 NPZ 有键图即可；若需要保留键的通用文件结果，在原 RDKit 图上写生成的构象，用 RDKit `SDWriter` 输出 SDF。套件 [`AtomicStructureVisualizer.write`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/visualization/structure.py#L58-L63)配 ASE 可写坐标，但 XYZ 不携带键；[`molecular_graph_to_rdkit`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/visualization/adapters.py#L29-L43)接离散图而不接生成坐标。入口与落盘格式待设计确认。

**后续验证建议：** 用不同原子数、含孤立节点及无边样本对拍拼批、末尾小批和设备交接；用恰在阈值、重合点、跨图同坐标、>32 候选与重复边（含零类型）逐数组对拍。公开采样用同一有键图比对单批和 dataloader 回传，查复本数、原子顺序和坐标；若选 SDF，回读再核对显式 H 与键。

## 词表：当前不新增 `Vocabulary`

`Vocabulary` 配置接入的是命名词表资源：[工厂](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/vocab/__init__.py#L22-L81)下载、校验和解析 JSON，以 token 次序生成索引，[模型工厂](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/__init__.py#L202-L268)再注入。GeoDiff 的 [SchNet](../geodiff_paddle/models/encoder/schnet.py#L131-L148)与 [GIN](../geodiff_paddle/models/encoder/gin.py#L74-L103)直接把原子序数用作各自 100 行嵌入的行号。[现有 `infgcn_qm9` 词表](https://paddle-org.bj.bcebos.com/paddlematerials/assets/vocabs/infgcn_qm9.json)把碳映射到索引 0，GeoDiff 用索引 6；替换会让已发布权重查错行。键嵌入也直接索引 [RDKit 键编号](../geodiff_paddle/utils/chem.py#L9-L15)、半径 `0` 和高阶键（[边嵌入](../geodiff_paddle/models/encoder/edge.py#L32-L55)）。因此保留数据及权重编号，不挂空词表，也不把扩散常数塞进词表；仅在引入实际外部词表资源时接入该工厂。

## 原生权重和 BCE 发布

1. **本地先按套件接口加载。** 本次通过文件元数据确认 `runs/paddle_qm9/qm9_default.pdparams` 存在，大小 `6,410,616` 字节；[已验收记录](../GeoDiff迁移实验记录.md#原生-pdparams-权重与-l1-梯度对齐)的 198 个状态项含 98 个共享别名。它是模型状态，不是训练断点。保留 [LayerList 的共享层路径和扩散表](../geodiff_paddle/models/epsnet/dualenc.py#L21-L60)，不额外套一层改参数前缀。训练和采样复用 [公共 `load_pretrain`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/utils/save_load.py#L44-L79)，不移植独立 loader；它对缺失或多余键只警告，所以验证时对齐键、形状、dtype、别名及缓冲值，再比真实输出。旧 `.pt` 的[一次性转换](../tools/convert_released_weights.py#L22-L62)留在独立仓。
2. **确认发布包后登记，不猜 URL。** 推荐发布名 `geodiff_qm9_default`（来自[作者检查点名](../geodiff/README.md#L52-L64)）。按[模型包契约](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/model_package.md#L1-L15)组织 `geodiff_qm9_default.zip` → `geodiff_qm9_default/` → `geodiff_qm9_default.yaml` 与 `checkpoints/best.pdparams`。`best` 是套件命名，不是本次重新训练的最优结果。发维护者确认分发和 BCE 地址，回传真实地址后填 `MODEL_REGISTRY`，用 [`build_model_from_name`](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/models/__init__.py#L271-L294)和注册名采样走一遍真实下载、解包、构建、加载；`Trainer.resume_from_checkpoint` 只接套件自己的训练状态（[公共断点加载](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/ppmat/utils/save_load.py#L159-L214)）。
3. **数据另包。** 本次核对的本地数据及导出目录中，只有作者原发布 `.pkl` 和两图的原生小样本 `train_2.npz`/`val_2.npz`，没有完整的 Paddle split 包。先明确来源、分发许可和获取路径；如果有正式上传位，按同一 schema 离线导出完整训练、验证及采样所需切分，用现有带 MD5 的数据下载机制。模型包与数据包均不入代码仓，迁移日志不当作 README 数据获取指南。

## 建议实施顺序与验收

1. **隔离分支、确定范围。** 完成设计讨论后，从核对过的 PaddleMaterials `upstream/develop` 另开 `feat/geodiff` 或工作树；不在 `feat/chemeleon` 上动。先落本项目的规格和工单，再按套件目录提交实际用到的 GeoDiff 默认路径。
2. **先证实模型和数据适配没有改变输入或数值。** 用公共构建器装配 YAML、NPZ 数据和原生权重。复用本地 9 原子固定输入，重新分别加载同一 Paddle 权重，比较有序边索引、类型、掩码、边长和两路分数；再用录制的时间步与噪声比对逐原子 loss/梯度。已有 [RTX 4060 Ti、FP32 对齐](../GeoDiff迁移实验记录.md#qm9-固定前向与-20-步训练实测)只作迁移参考，不能替代接入回归。图算子、扩散建表等数值替换单独过门。
3. **训练和采样走公开入口验证。** 一个小批次过一次真实更新和验证；用可区分的两组损失使两路 LR 按各自指标变化，验证全模型联合裁剪与断点恢复，不能只测共同下降的损失。用同一有键图、固定初始坐标及噪声检查少量反向步、结果维持原分子拓扑；分别验证本地和注册权重路径，真实包地址提供后再验后者。不跑全量复训、长链基准或测试集指标。
4. **文档和发布收尾。** 在 `structure_generation/configs/geodiff/` 给出英文模型 README、模型图或有署名的来源、数据获取、训练与采样命令、论文引用；在 [领域矩阵](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/structure_generation/README.md#L7-L36)区分晶体和分子能力，发布时同步[套件预训练模型表](https://github.com/PaddlePaddle/PaddleMaterials/blob/develop/docs/models_overview.html#L201-L220)及实际引用它的首页与根 README。按[贡献措辞规范](../../工作总结/ppmat贡献交付注释与措辞规范.md)保留简洁英文、Paddle 文件头及实际引用的 [GeoDiff MIT](../geodiff/LICENSE) 和 [图算子](../geodiff_paddle/graph_ops/UPSTREAM.md#L1-L10)/[数据类型来源](../geodiff_paddle/graph_data/UPSTREAM#L1-L2)所需的原许可证与署名。精度对齐的实测条件放 PR，套件 README 只写用户要用的信息；这是 [Chemeleon README 反馈](https://github.com/PaddlePaddle/PaddleMaterials/pull/322#discussion_r4608507665)最接近的先例。通过相关 pytest 和套件 pre-commit 再发向官方 `develop` 的 PR。
