# GeoDiff PaConvert 转换与 Paddle 兼容性调研

2026-11-23。参照本地 GeoDiff Torch 代码及已确认的 GIN 兼容补丁。工具是 `paconvert 3.3.1`，目标环境是现有 `paddlepaddle-gpu 3.4.0`；Torch 基线为 `2.11.0+cu128`、PyG `1.7.2`、torch-cluster `1.6.3` CUDA。下文是静态核对与改法建议，未导入或运行 Paddle 镜像，未手改镜像或 Torch 源码。Paddle 的 [develop API 映射及差异表](https://www.paddlepaddle.org.cn/documentation/docs/zh/develop/guides/model_convert/convert_from_pytorch/pytorch_api_mapping_cn.html) 用来查候选，是否可用和需保留的语义以目标 3.4 文档、源码和后续测试为准。

## 1. 实际转换结果

```sh
paconvert -i geodiff -o geodiff_paddle --show_unsupport_api --no_format 2>&1 | tee paconvert.log
```

[原始日志](../paconvert.log#L718-L745)计数：560 次 API，558 次报告成功，2 次不支持（99.64%），**只有一个不支持的 API**：`torch.sparse.LongTensor`。源文件 [models/common.py](../geodiff/models/common.py#L183-L228) 两处，镜像 [models/common.py:166、187](../geodiff_paddle/models/common.py#L162-L193) 保留 `>>>>>>` 标记。对镜像的 22 个 `.py` 做静态解析：只有该文件报 `SyntaxError`；去掉标记只足以解析文本，原调用和运行依赖仍在。两侧各 30 个文件：转换器省略 `.gitignore`、生成 `paddle_utils.py`；其他同名非 Python 文件逐字节相同。复制过来的 [`env.yml`](../geodiff_paddle/env.yml#L177-L209) 仍是作者的 Torch 环境清单，不能拿来安装 Paddle 镜像。转换率不是可运行率或数值对齐证据。

## 2. 显式失败与静默误改

| 类别 | 镜像中已核对的问题 | 建议改法与最小证明 |
|---|---|---|
| **共用 COO 路径，2 处明确失败** | 半径图把高阶/键图与半径候选图相加再 coalesce，转换器不识别旧的稀疏 LongTensor 构造。 | 以坐标和值做一次合并，不改截断、隔离或类型规则。下面列出两种原生改法，先用重复坐标和类型 `0` 的手算图证明。 |
| **构造器与名称绑定** | [MLP](../geodiff_paddle/models/common.py#L54-L68)、[GINE/GIN](../geodiff_paddle/models/encoder/gin.py#L9-L24) 共 3 处 `getattr(F, ...)`，导入已丢失；GINE 还把原版 `self.nn = nn` 变成 `self.nn = paddle.nn`，但 [forward](../geodiff_paddle/models/encoder/gin.py#L25-L46) 仍调用 `self.nn(out)`。 | 明确使用 `paddle.nn.functional`，恢复构造器收到的 MLP，保持 `.nn` 参数键和激活顺序；用一条有向边和孤立点检验层的输出与反传。对照[原 GINE](../geodiff/models/encoder/gin.py#L15-L59)，不顺便更换模型激活、跳连或局部用到的编码器。 |
| **对 NumPy 的变量误套 Tensor 方法** | [COV/MAT](../geodiff_paddle/utils/evaluation/covmat.py#L17-L38) 分配的是 NumPy RMSD 矩阵，3 处原生 `ndarray.min(axis)` 被改成 `._min`，而生成的 [helper](../geodiff_paddle/paddle_utils.py#L7-L43) 仅修改 `paddle.Tensor` 类型。另两处 [datasets](../geodiff_paddle/utils/datasets.py#L210-L218) 的标量 min 和 [cluster](../geodiff_paddle/utils/datasets.py#L289-L298) max 真是张量。 | 原样保留 NumPy 按轴 `min`，张量用原生 `paddle.min/max`，不用全局 `setattr`。对照[原评估器](../geodiff/utils/evaluation/covmat.py#L15-L44)，原来已过时的 NumPy dtype 别名是存量问题，不能与这次误改混淆。用小的非方形 RMSD 矩阵验证参考/生成侧轴。 |
| **设备和 dtype** | 训练/采样把模型放到目标设备，却没有设置全局 place；[扩散 loss](../geodiff_paddle/models/epsnet/dualenc.py#L176-L196) 的 `randint` 没了原来的 `pos.device`，输入和时间步可能不同 place。 | 入口显式设置 place，并验证随机数、索引和坐标同 place：节点/边/时间步用 int64，掩码 bool，坐标/分数 float32。已支持的 3.4 别名不当作故障，例如该版本 [ones/zeros](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/tensor/creation.py) 支持 `size` 和 `device`，[设备解析](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/device/__init__.py#L398-L430) 识别 `cuda`；不需要启用全局 Torch 代理。 |
| **checkpoint、optimizer、scheduler** | [训练恢复](../geodiff_paddle/train.py#L82-L92) 改成 `paddle.load(.pt)` 并丢掉原信任参数语义；又用 Torch 字典直接恢复、用 `.param_groups[0]['lr']` 打印。原版旧 `.pkl` reader 未变。 | 显式区分离线转换和原生 Paddle 加载。单组 LR 用 `optimizer.get_lr()`；在状态转换通过前，不把同权重新建 Adam 的冒烟叫续训。见第 4 节。 |

### COO：不支持的是旧构造函数，不是图的功能

[Paddle COO 差异页](https://www.paddlepaddle.org.cn/documentation/docs/zh/develop/guides/model_convert/convert_from_pytorch/api_difference/input_args_usage_diff/torch.sparse_coo_tensor.html) 映射 `size→shape`、`device→place`、`requires_grad↔!stop_gradient`；[3.4 稀疏构造文档](https://www.paddlepaddle.org.cn/documentation/docs/zh/3.4/api/paddle/sparse/sparse_coo_tensor_cn.html) 支持 int64。可把两路坐标和值各自拼接一次后构造并 coalesce，不必造两份稀疏张量再相加；3.4 的 [CPU](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/paddle/phi/kernels/sparse/cpu/coalesce_kernel.cc) / [GPU](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/paddle/phi/kernels/sparse/gpu/coalesce_kernel.cu) coalesce 有 int64 实现。不过 3.4 的 [eager COO 构造器](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/sparse/creation.py#L145-L171) 会查索引最大值并转到主机；空边和 GPU 同步是需单独处理的边界。

建议默认一路用 int64 `src*N+dst` 键，原生 [`unique` 的 inverse](https://www.paddlepaddle.org.cn/documentation/docs/en/api/paddle/unique_en.html) 加 [`index_add`](https://www.paddlepaddle.org.cn/documentation/docs/en/api/paddle/index_add_en.html) 求同键类型和，最后按行列升序解码。按坐标去重，不按值去重：[Torch COO](https://docs.pytorch.org/docs/2.11/sparse.html#uncoalesced-sparse-coo-tensors) 的重复条目相加，GeoDiff 的 **半径独有边存在且类型为 `0`**，不能对合并后的类型值做 `nonzero`。重合的默认半径候选不会覆盖原有正类型。高阶邻接矩阵中的 `0` 才表示无边，这两处不能共用取边规则。

## 3. 未转换的 Torch 生态库与构图

按镜像 Python AST 统计 `import` / `from` 语句（在内存中剥离语法标记，仅用于统计；未改文件）：

| 依赖 | 语句 / 文件 | 处置和工作量 |
|---|---:|---|
| `torch_geometric` | 21 / 12 | `Data`/`Batch`/加载、`MessagePassing`、邻接工具、`Compose`、半径图包装。主链无需移植 PyG 库。拼批和消息归约逻辑小，半径图和兼容旧数据的代价更高。 |
| `torch_scatter` | 6 / 5 | 训练 [等变回写](../geodiff/models/geometry.py#L1-L21) 和编码只需要显式输出大小的分组求和；采样中心化要分组均值，粗粒化另有 `max`。[`ppmat.utils.scatter`](../../PaddleMaterials/ppmat/utils/scatter.py#L114-L138) 已有 Paddle 实现，直接复用前核对 dtype、空组和梯度；其公开 sum/mean 见 [scatter.py](../../PaddleMaterials/ppmat/utils/scatter.py#L244-L276)。不用为了默认路径移植其他归约。 |
| `torch_sparse` | 5 / 5 | 高阶图用重复坐标求和的 `coalesce`；用上述小函数覆盖实际调用。GINE 的 `SparseTensor` 类型分支和可选输入单独评估，不冒称已支持。 |
| `torch_cluster` | 0 直接 / 经 PyG | 旧 PyG 包装实际执行邻居选择，是最容易静默改变图的算子；需复现下面的 CUDA 约束。 |
| `torchvision` | 0 / 0 | [可选绘图](../geodiff_paddle/utils/chem.py) 的 `to_tensor` 已改 Paddle；有[官方差异页](https://www.paddlepaddle.org.cn/documentation/docs/zh/develop/guides/model_convert/convert_from_pytorch/api_difference/invok_only_diff/torchvision.transforms.functional.to_tensor.html)。这是后续绘图验证，不是默认训练需要的 Torch 依赖。 |

三组残留导入合计 **32 条，去重后 14 个文件**；另有两个 `torch.sparse.LongTensor` 未转换引用。`RDKit`、NumPy、NetworkX 与 YAML 继续保留；官方 `.pkl` 缠着 Torch/PyG 是序列化边界，并不需要重做 RDKit 化学计算。

- **半径边：按实际 CUDA 基线，不按名称猜语义。** [PyG 1.7.2](https://github.com/pyg-team/pytorch_geometric/blob/1.7.2/torch_geometric/nn/pool/__init__.py#L171-L210) 默认方向 `[source,target]`、`max_num_neighbors=32`、`loop=False`。[torch-cluster 1.6.3 包装](https://github.com/rusty1s/pytorch_cluster/blob/1.6.3/torch_cluster/radius.py) 请求 **33 个含自身的候选名额**，之后才去自环，不二次截断。[CUDA 核](https://github.com/rusty1s/pytorch_cluster/blob/1.6.3/csrc/cuda/radius_cuda.cu) 在同分子内按源原子原索引递增、严格 `< r²`、满额即停；若自身没进这 33 个名额，可留下 33 个非自环邻居。不是最近 32 个，也不保证对称。[CPU](https://github.com/rusty1s/pytorch_cluster/blob/1.6.3/csrc/cpu/radius_cpu.cpp) 用不按距离排序的 KD 树结果，超限时不冒称等价。复用 [ppmat SphereNet](../../PaddleMaterials/ppmat/datasets/graph_utils/spherenet_graph_utils.py#L19-L63) 的按分子算距离思路，不直接复用其「去自环后返回所有半径边」。建议有界块上用按源列 cumsum 选择候选，再去自环；只在选择拓扑时不跟踪梯度，随后从原 `pos` 计算边长。侧链的 raw `radius` 是 cap 32、映射并加反向边后去自环，不能混成同一个默认入口。[模型分支](../geodiff/models/common.py#L194-L228)
- **高阶边：复现最短跳数，不重复扩图。** [PyG 1.7.2 `to_dense_adj`](https://github.com/pyg-team/pytorch_geometric/blob/1.7.2/torch_geometric/utils/to_dense_adj.py) 为重复坐标累加属性；[`dense_to_sparse`](https://github.com/pyg-team/pytorch_geometric/blob/1.7.2/torch_geometric/utils/sparse.py) 读非零坐标。用 Paddle 原生 `scatter_nd_add` 和矩阵乘法（3.4 CPU/GPU 的 [int64 注册](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/paddle/phi/kernels/gpu/matmul_kernel.cu)）算至三跳，保留原键类型，高阶类型沿用 `len(BOND_TYPES)+hop-1`。训练中用扰动后坐标重建半径边；采样 [`AddHigherOrderEdges`](../geodiff/utils/transforms.py#L39-L58) 已预扩高阶并 [关闭重复扩展](../geodiff/test.py#L99-L125)。两处共享高阶实现；不为满批跨分子零块分配矩阵。空键和尾部孤立点单测；原旧 PyG 的全空邻接走 `.max()`，补空边行为不能称逐项复刻了旧异常。
- **消息传递：只搬实际计算。** 原 [CFConv](../geodiff/models/encoder/schnet.py#L70-L100) 是 `lin1(x)[src] * W` 后按 `dst` 加和再 `lin2`；原 [GINE](../geodiff/models/encoder/gin.py#L33-L59) 是按边激活再目标归约，加 `(1+eps)·x_dst`，最后过注入的 MLP。沿用 [PyG 方向](https://github.com/pyg-team/pytorch_geometric/blob/1.7.2/torch_geometric/nn/conv/message_passing.py#L137-L181)，`gather` 和显式 `N` 行归约，孤立点不掉行。ppmat 确有 [Paddle MessagePassing](../../PaddleMaterials/ppmat/models/common/message_passing/message_passing.py#L25-L65)，但它进口的 [`paddle_aux`](../../PaddleMaterials/ppmat/utils/paddle_aux.py#L61-L76) 修改全局 Tensor 方法；独立镜像建议直接用原生原语，不为两个向前层引入整套适配。全局编码器看整张合并图，只有全局 **loss** 排除局部边；局部分支继续使用上游现有的 `edge_encoder_global`，不改为另一组权重。[原模型](../geodiff/models/epsnet/dualenc.py#L186-L230)
- **拼批：按数据字段拼，不 `stack` 分子。** [Paddle 3.4 DataLoader](https://www.paddlepaddle.org.cn/documentation/docs/zh/3.4/api/paddle/io/DataLoader_cn.html) 的第二个位置参数不是 batch size；显式用 `batch_size=` 和 `collate_fn=`。拼接 `atom_type/pos`，两行 `edge_index` 加同一节点偏移，保留 `edge_type`、`batch`、`num_nodes_per_graph`、`num_graphs` 和原样本顺序。ppmat 已有 Paddle/NumPy [`Data`](../../PaddleMaterials/ppmat/datasets/geometric_data_type/data.py#L183-L238)、[`Batch`](../../PaddleMaterials/ppmat/datasets/geometric_data_type/batch.py#L54-L167) 和 [collator](../../PaddleMaterials/ppmat/datasets/collate_fn.py#L53-L85) 候选；交付时优先验证后复用，不用现成的 ppmat QM9 CSV 数据集替换 GeoDiff 官方构象。独立镜像只需要薄的字段拼批与采样需要的重复图操作。

## 4. 数据、模型状态和训练状态不是同一个转换

**离线资产边界。** 官方 `.pkl` 恢复旧 PyG 实例及 Torch 张量（[原 reader](../geodiff/utils/datasets.py#L777-L792)、[Python pickle 文档](https://docs.python.org/3/library/pickle.html#what-can-be-pickled-and-unpickled)）；官方 `.pt` 是 Torch 保存的状态、EasyDict 和迭代号。[Paddle `torch.load` 差异页](https://www.paddlepaddle.org.cn/documentation/docs/zh/develop/guides/model_convert/convert_from_pytorch/api_difference/torch_more_args/torch.load.html) 不承诺其反序列化或参数语义，[3.4 `paddle.load`](https://www.paddlepaddle.org.cn/documentation/docs/zh/3.4/api/paddle/load_cn.html) 文档讲的是 Paddle 保存格式。建议独立 Torch/PyG 只对可信官方文件做一次导出，Paddle 读纯数值数组（NPZ `allow_pickle=False`）与可读元数据，再保存原生 checkpoint。先用小批，完整官方 split 用拼接数组与节点/边偏移，保持键类型、显式氢、样本与原子顺序；COV/MAT 另保留同原子顺序的分子拓扑和参考构象，不能只用 SMILES 重猜键。采样、评估和训练三者不混用格式。

**层权重。** 镜像用 `paddle.compat.nn.Linear`，它和 [Torch Linear](https://docs.pytorch.org/docs/2.11/generated/torch.nn.Linear.html) 都是 `[out,in]`（[Paddle 3.4 compat 实现](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/compat/nn/__init__.py#L554-L590)）。换原生 [`paddle.nn.Linear`](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/nn/layer/common.py#L209-L236) 后才转置 **Linear 权重**与同布局 Adam 矩，方阵也转；Embedding 和 bias 不转。建议用原生层以便向 ppmat 交付；保留兼容层可少做这个布局转换，不引入 Torch 本身。严格校验目标键、形状、dtype，核对直接挂载的层与 `model_global/local.{0,1,2}` 的同一实例别名，保留 `eps`、发布的 `betas/alphas` 及其非训练属性。不用 `strict=False` 隐去错误；无梯度的局部 edge encoder 不伪造有效 Adam 状态。[模块注册](../geodiff/models/epsnet/dualenc.py#L61-L130)

**优化器与调度器。** [Torch Adam/状态字典](https://docs.pytorch.org/docs/2.11/generated/torch.optim.Optimizer.state_dict.html) 以参数 ID 和组的顺序配对；Paddle 3.4 的 [Adam](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/optimizer/adam.py#L299-L431) / [optimizer](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/optimizer/optimizer.py#L402-L522) 使用命名 moment 与 beta-power accumulator。离线用 Torch 每分支的参数名单解析 ID，装配两个独立状态，保留缺梯度/缺状态的区别；每个活动参数已完成 `n` 次后，Paddle 普通分支下一步读 `beta**(n+1)`。数百万步的 float32 power 不能倒推出整数 step，单独记录实际计数。[Torch GPU foreach](https://github.com/pytorch/pytorch/blob/v2.11.0/torch/optim/adam.py#L770-L800) 和 [Paddle 普通 GPU 核](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/paddle/phi/kernels/gpu/adam_kernel.cu#L40-L157) 的 epsilon 位置数学上相同，不能仅凭 docstring 宣称不同或重缩放；验证实际派发路径。包含高步数状态、极小梯度、无梯度槽的单步比较，通过后才比较五步续训。

[原版](../geodiff/train.py#L147-L204) 每次验证给两个 Plateau 分别喂本分支按节点均值。Paddle [`ReduceOnPlateau`](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/optimizer/lr.py#L1551-L1684) 按每路转换 best/bad/cooldown/last_epoch/last_lr，并保留 factor、patience、阈值、epsilon 等参数；检查实际配置的边界，不为所有 cooldown 模式宣称等价。验证之前用 checkpoint 的 LR（本次 `2.1936950640377836e-8`），不是 YAML 的 `1e-3`。日志改 `get_lr()`；全模型去重参数裁剪一次并记录裁剪前范数，用 [Paddle `clip_grad_norm_`](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/nn/utils/clip_grad_norm_.py#L73-L119) 和可重迭代列表，不拆成两个优化器各裁一遍。清梯度保留 None 语义（原生 `clear_grad(set_to_zero=False)`）。现有五步范数都小于裁剪阈值，另用会触发缩放的小算例验证。默认路径先用双优化器原生循环；ppmat 的 [OptimizerList](../../PaddleMaterials/ppmat/optimizer/optimizer.py#L478-L510) 和 [trainer 的单指标调度](../../PaddleMaterials/ppmat/trainer/base_trainer.py#L725-L747) 不能不经验证就替换这两个 LR 和两路指标。

## 5. 建议的验证次序（未执行）

1. **去 Torch 的静态与算子门槛。** 默认入口的导入、配置、数据和权重加载不能借当前 `paddletorch` 中的 Torch 才成功。可在独立进程验证默认路径未加载 Torch 生态，并检查依赖清单。先验两个不同大小的分子拼批、重复边加和、跨图隔离、孤立节点、严格阈值、纯半径边类型 `0`。首个官方 QM9 验证样本的 Torch 观测是 18 原子、36 有向键，最终 306 边，其中 140 条纯半径边；数字吻合还需核对坐标/类型数组。加一个 35 个近邻、坐标顺序不同于距离顺序的图：CUDA 的目标 0 有 32 个非自环邻居，目标 34 可有 33 个。固定前向的小图不覆盖这个上限。
2. **固定输入直接前向。** 另开一个加载官方模型状态的实例，读已有 `forward.npz` 的输入，在 eval 下直接去噪，不跑扩散采样。比较有序边索引、边类型、局部掩码完全一致；边长和 `(32,1)`、`(30,1)` 全局/局部分数做逐元素误差和最大/平均误差。先定位构图，再比各路输出；不只看形状和范围。分数为 float32，不要求 GPU 浮点按位相同。运行前约定首轮阈值，例如 `atol=1e-5, rtol=1e-4`，失败先定位误差，不事后放宽当作通过。
3. **Paddle 单卡真实数据冒烟。** 从同一官方权重起步，用导出的最小官方训练/验证 batch 确认读数、构图、两路 loss、反传、一次原生双 Adam 更新与原生 checkpoint 重载；可用新建 Adam，只记作「同权重冒烟」。前向和训练各从头加载，不让 `Embedding(max_norm=10)` 的查询修改另一个试验的起点。
4. **同输入的更新前 loss、梯度。** 从发布起点单独重载，用 `inputs/2865000.npz` 捕获的实际原子批、最终 `time_step` 与 `pos_noise` 替换抽样输入，不改扰动或损失公式。先比边、按原子两路 loss、总 loss、梯度是否存在与全局范数。已有 Torch 结果只有逐步标量和输入；逐原子损失或逐参数梯度要从已确认的 Torch 参考另取。两框架各设置同一 seed 不保证权重初始化、shuffle 或扩散噪声相同。[Torch 随机性说明](https://docs.pytorch.org/docs/2.11/notes/randomness.html)
5. **五步续训最后验证。** 两个 Adam/调度器转换的最小单步测试分别通过后，再重放 5 个训练 batch，记录原编号 `2865000–2865004`、两个 Adam 活跃计数 `2865005`，按步比较 loss、两路 LR、参数更新和矩。首末验证各用同一官方样本批，但实际时间步与噪声没有保存。可喂历史两路指标，验证调度器状态，不叫验证 loss 复现；且 [Torch](https://docs.pytorch.org/docs/2.11/generated/torch.nn.Embedding.html) 和 [Paddle](https://github.com/PaddlePaddle/Paddle/blob/v3.4.0/python/paddle/nn/functional/input.py#L137-L165) 的 `Embedding(max_norm=10)` 即使在 eval/no_grad 也可能原地改访问过的权重，跳过 eval 前须证明权重不变。若需完整含验证的轨迹，应另录真实验证 t/噪声和事件前后状态，明确是新 Torch 参考，不复称当前五步历史轨迹。

固定前向 NPZ、五个训练输入 NPZ、首末 post-validation checkpoint 和官方起点目前均可定位。`runs/` 清理前应保留这些要做逐元素比较的最小文件；[实验记录](../GeoDiff迁移实验记录.md) 已保留数值与条件，但不能从标量反推出数组和优化器状态。第一次输出的 `2865000.pt` 已执行一次更新和验证，不是官方起点。

首轮建议只验单卡 QM9 的默认 diffusion 核心链路。Drugs、扩散采样、COV/MAT、性质评估、DSM、侧链、粗粒化及通用稀疏 GINE 接口保留为不同验收路径，不删除或插入空实现。原版已有侧链 `pos_gt` 未绑定等问题（[原 sampler](../geodiff/models/epsnet/dualenc.py#L348-L359)），不借默认主链迁移偷偷改算法。ppmat 接入按[项目贡献报告](../../工作总结/PaddleMaterials贡献流程与CINN接入调研报告_2026-09-07.md)和[原生成模型/Trainer 契约](../../PaddleMaterials/docs/trainer_docs.html)另验；本轮不做框架注册、CINN、国产卡或任何后续实现决策。
