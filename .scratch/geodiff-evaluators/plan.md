# GeoDiff optional evaluation implementation plan

**当前执行范围：** 仅 `feat/geodiff` 的 COV/MAT。用户同意新生成构象 SDF 加入来源标识，已放弃量化性质。本轮不改模型、默认依赖、训练和采样默认值或已有四包。[规格](spec.md)与[构象工单](issues/01-covmat.md)为准。以下保留首次受限尝试的规划记录。

## 先证明基准

[构象质量](issues/01-covmat.md)和[量化性质](issues/02-properties.md)各自先跑原作者 Torch 评估；预检可并行，不改参考或套件。保存相同输入、期望数组、来源、实际环境与完整失败原因到本仓忽略的 `runs/`。只试一个分子/小集合。性质试验不共享两端结果缓存。必要时取已由发布权重生成并验证的 5,000 步构象，不为测试重跑整条链。

## 通过基准再写功能

1. 父任务用一条薄 CLI `python -m structure_generation.evaluate_geodiff {covmat,properties} --reference <NPZ> --generated <SDF>` 作共同验收面；只公布通过基准的子命令。将可靠的身份配对和原子顺序检查限定在评估私有数据接口。默认按模块运行，无额外安装、注册或权重加载，仅写用户明确请求的输出或 stdout。
2. 先红后绿：子任务各自写指标输出行为测试，控制端跑最窄测试；未见真实红前不写指标计算。两种计算不共用结果缓存。父任务用同一 SDF 回读坐标向作者 oracle 与套件喂数，核对逐分子与总体输出。证明可区分参考侧、生成侧，样本不足或未配对不可当全零分。
3. 针对实际改动做 spec/质量检查、定向测试和贡献格式检查；公开 CLI 使用和例子只记录已通过的功能，不能写论文成绩。未动分组训练、原模型、四个候选包；不做发布工作。

## 停止与交接

无须追加批准的是：已有/隔离测试环境里调用原接口、可选后端只在显式使用时导入、NPZ/SDF 只读。触及新的全套件依赖、大型历史环境重建、第三方/参考代码补丁、含糊配对或共享架构变更时立即报告，不拆掉检查、不换基准。独立未受影响的一项可完成，公共阻塞时两项都停。证据和暂停的最小后续选择记回工单与根日志。
